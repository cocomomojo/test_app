# 役割別チェックリスト

## 👨‍💻 開発者向け

### PR作成前

- [ ] 変更概要を説明できる
- [ ] 影響範囲を説明できる
- [ ] unit / integration の追加・更新を確認した
- [ ] E2Eが必要な変更かを考えた
- [ ] AIを使った場合、その用途を説明できる

### PR作成時

- [ ] PR本文に変更理由を書いた
- [ ] 影響する画面 / API を書いた
- [ ] 追加・更新したテストを書いた
- [ ] 手動確認ポイントを書いた

---

## 🧪 QA向け

### テスト設計時

- [ ] 観点の抜け漏れを確認した
- [ ] 他工程で担保済みの観点を除外した
- [ ] E2Eにすべき観点を絞った
- [ ] Manualに残すべき観点を明確にした
- [ ] デシジョンテーブル削減時の理由を残した

### レビュー時

- [ ] AI提案をそのまま採用していない
- [ ] 高リスク観点を保持した
- [ ] 削減理由を説明できる

---

## 👀 レビューア向け

### 承認前

- [ ] 変更内容とテスト観点が対応している
- [ ] 過剰テスト / 不足テストの偏りがない
- [ ] E2Eの数と粒度が適切
- [ ] 高リスク変更を人が十分確認している
- [ ] AI利用箇所の最終判断が明確

### 差し戻し判断の例

- [ ] 業務上重要な観点が抜けている
- [ ] E2Eでなくunitで見るべき観点が多い
- [ ] 不要ケース削減の理由が弱い
- [ ] AI提案の妥当性確認が不十分
